## Questions for the operator

1. **F02, §16.6 (signs task 0265).** A worker's suite run that finds the exclusive lane held is
   refused (exit 75) and reruns by hand; no prompt names `--wait`. Options: (a) the four change
   prompts and the verify prompt render `--wait auto` on their full and gate lane commands (a
   template change after 0257, and §16.6's "the worker does other work and retries" changes);
   (b) a run bound to a worker run and given no `--wait` waits as `--wait auto` does, `--wait 0` and
   unbound runs keep exiting at once (one code site, every product and every hand-typed worker command
   covered, no template change); (c) keep it. Recommendation: (b). Signing 0265's brief accepts (b),
   the corrected "counts as the full role's lane" wording, and the passage's last sentence ("A run whose
   wait ends with the lane still held exits the same way…"), which describes what the code already does.
   Another answer means the lead rewrites 0265 before you sign.
2. **F04, the release rule.** A merge to main is a release (ADR-0024) and moves the run checkout
   while other tasks are in flight; ADR-0031 still says runner-driven work comes later and needs its
   own release rule. Options: (a) release at any time: tasks in flight carry on, their workers run the
   head they change (0240), and only the runner's and lead's own `ccp` calls move to the new release;
   (b) release only between tasks: the runner drains every task in flight before `scripts/release.sh`,
   which serialises the plane at each merge; (c) release at a review point's close only, which
   departs from ADR-0024 ("merged is released"). Recommendation: (a), recorded as a new decision in
   ADR-0031, with D1's "comes later" and the consequence's open release rule retired; the lead writes
   it once you answer.
