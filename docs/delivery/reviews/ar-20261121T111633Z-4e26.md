## Question for the operator

F01: §19.6 item 3 makes an architect pass due at 3 friction notes since the last pass, counting
every line, and every `--allow-overdue` is itself recorded as a counted note. Workers write about 3
notes a task (often one issue restated by each seat), so a pass is due after about one merge, 0211's
cadence of 12 merges never governs, and the runner overrode the gate 22 times in 9 hours. Options:
(a) the gate's own `allow-overdue` notes do not count, and the trigger counts distinct tasks with a
worker note rather than lines; (b) the threshold scales with `parallel.max_in_flight`, as 0211 did
for the cadence; (c) both; (d) keep the rule. In each of (a)-(c), §19.6 item 3 states the behaviour
and leaves the number to code (E10); the answer becomes one task with a signed brief.
Recommendation: (c). Leaving out the override notes ends the self-feeding loop; counting tasks
rather than lines stops one issue restated by three seats from counting three times; scaling by
tasks in flight keeps the trigger in step with the cadence (17 tasks had notes in this window, so
with 3 x 3 a friction pass comes after about 9 noted tasks, close to the 12-merge cadence, instead
of after one).

**Answer (the operator, 2026-11-21, in the lead session): "F01 - (c)".** Both: the friction trigger
counts the distinct tasks with a worker's note, leaving out the plane's own override notes, and its
threshold is a constant times `parallel.max_in_flight`, as for the cadence. §19.6 item 3 states the
behaviour and leaves the number to code (E10). Task 0270 (R22, `sign_off: brief`) carries the §19.6
text for signature.
