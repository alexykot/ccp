**Summary (the architect's).** ADR-0044 is small, and the code is mostly ready for it: report sections already share one parser (`report.friction(text, heading)`), the run record is the obvious store, and the review-point summary already maps tasks to points. Three things need a decision before tasking. (1) Where D3's check runs: `ccp tasks check`'s validator is shared by `docs check`, the verifier's gate, every implementer gate and the reconcile, so a queue-state failure placed there would block unrelated tasks, depending on whether a worker's shell has QUEUE_ROOT. (2) E5 says records hold numbers and ids only, and D1 stores worker text on the run record. (3) The briefs already give out-of-scope work two routes, one of which the ADR rejects. Most of the change cost is incidental: the report's format is restated in seven places and pinned by brief-wording tests, and SPEC §11.1, which the ADR edits, is already wrong about the run record. Two friction notes are confirmed with my own evidence: dod_checks grep exact SPEC prose (note 1), and they run the released `ccp` from PATH (note 3). I could not confirm the E3 leak-check flip (note 2): no probe is allowed, and the check reads a denylist that lives outside the tree.
