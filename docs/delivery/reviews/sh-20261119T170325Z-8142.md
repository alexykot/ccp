**Summary (the architect's).** ADR-0043 is mostly a configuration change, and most of it lands in
`ccp/config.py`, which most `ccp` and test modules import, so every task of the ADR touches nearly the
whole suite. The main risks: code outside `config.py` keeps its own copy of the defaults D2 and D7
change; the "one default, held by a test" rule (E12) is enforced for one block; the shared test
fixtures rely on today's defaults, so each flip would break dozens of modules at once; the Python
facts D4 hands to a language pack live in four places; and several keys the appendix calls dead are
still read. Not checked by the shape: whether a project directory can turn telemetry off locally.

**Checked against the head above.** Every finding reproduces; some counts are off:
- F01 misses a fourth raw reader, `scripts/sync-product-docs.sh` (`architect.rules_doc`).
- F02: the key sets of most blocks are already tested; what drifts is `estimate.calibration` (accepted
  by code, rejected by the schema) and 31 keys with no schema `default`. Only `parallel`'s default
  values are tested.
- F07: ten binding parser functions (`_scalar` copies in `ccp/init.py` and `ccp/otel.py` among them)
  plus six inline regex readers, not six.
- D7's "after two failures in a row it stops blocking" is already built (`failed_in_a_row`).
- D6's open question (a local telemetry-off) is answered from §24.1: Claude Code ignores the enabling
  keys in a project's settings, so a project directory cannot turn telemetry off; 0184 says so.
- The ADR's grace release has no mechanism in code, and §8.1 and §29.3 say the schema "only gains
  optional keys"; 0182 adds the grace rule to §29.3, and 0191 ends the grace.
