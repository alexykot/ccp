**Summary (the architect's).** ADR-0040 is easy to build, because all PR-host access is in four call sites across three modules (lifecycle.py, verify.py, prompt.py). The catch is that GitHub's JSON leaks well past those call sites: the state names MERGED and OPEN, headRefOid, headRefName, mergeCommit.oid, mergedAt and body are read inside close, drop, catch-up, merge-ok and the review body check. Each site also looks up CCP_GH_BIN on its own. The main shaping risk is that D1/D3's five operations do not cover what the code already reads and writes: the merge time, the head branch, the PR body and editing the body. That needs a decision before the local adapter is tasked. On the test side, the shared fake gh (used by 62 modules, including the slowest) already behaves like the D3 local adapter, so it can be replaced by the real adapter. `ccp verify check`, a weaker second merge gate kept for 'merge steps without gh', loses its reason to exist. There were no friction notes to confirm. I could not run any probe beyond read-only git and file commands, so subprocess-spawn counts and per-test timings are inferred from the code and the health summary.
