## Questions for the operator

1. **F01, §20.6 (signs task 0271).** `ccp mutate` takes one `--test` per call, runs a mutant that
   changes nothing, and does not say which test failed, so seats rerun it (12 notes in one window).
   Options: (a) `--test` repeats, a mutant is killed by the first named test that fails, a
   substitution whose new text is its old is refused, and each row lists the failing test ids;
   (b) only the no-op refusal and the failing ids, `--test` stays single; (c) no rule change: only the
   refusal message's line-break hint, which needs no SPEC text. Recommendation: (a). Signing 0271's
   brief accepts (a).
2. **F07, §6.7 (signs task 0273).** A not_built citation is refused only by `verify record`, after the
   verifier's whole round. Options: (a) `ccp prompt verify` refuses to open the verify (exit 1), as
   `record` would refuse its approve; (b) `ccp prompt verify` warns on stderr and opens; (c) no change.
   Recommendation: (a). Signing 0273's brief accepts (a); its other items need no SPEC text.
3. **F05 and the respawn scope, §13.2, §16.5, §21.1, §22.5 (signs task 0275).** Every seat's `ccp tasks
   check` prints a stale-Context warning per pending task (14 now), which only the lead or the
   implementer can act on; and a same-point respawn drops the tasks the lead added to the scope.
   Options: (a) one count line in `ccp tasks check`, `--stale` to name them, the implement prompt
   carrying its own task's warning, the spawn and its dry run listing the scope's, and a same-point
   respawn keeping the lead's added tasks; (b) only the respawn rule (§22.5), the warnings as they are;
   (c) no change. Recommendation: (a). Signing 0275's brief accepts (a); for (b) the lead rewrites 0275.
4. **Existing drift, §15.4 (deferred, no task).** §15.4 accepts a ruling that names gate ids when
   every gate is closed and approved, with no limit on class; `verify record` also refuses a waiver
   whose only ids are operator gates ("an operator gate approves running a step, never skipping it"),
   a rule only `verify._waiver_texts` holds (0237's fix round). Options: (a) §15.4 states the class
   limit (a § change, signed in a later task); (b) the code drops it and accepts any closed, approved
   gate. Recommendation: (a), since ADR-0045 D3 reads that way. Task 0273 follows the code as it is
   either way.
