**Summary (the architect's).** ADR-0042 lands on code that already has most of what it needs. Claim
rule 3 and the next walk go through one pairwise function (`parallel.clash`, which tests whether two
tasks' paths meet). Close's catch-up already merges with `git merge-tree` and unions shared paths. A
patch-id comparison already exists for the integration-merge rule. The main risks are in the build:
(1) D3 is worded as narrowing a review refusal that does not exist: today only verify refuses a head
behind the tip. (2) The merge-tree and patch-id probes the ADR needs five times exist as two separate
copies, written differently. (3) D2 and D4 disagree on what declared paths still do at close under
`clashes`. (4) D4's new close branches would go into the suite's slowest module.

Every finding was checked against the head above; all reproduce. Counts have moved slightly since the
report: `tests/test_behind_tip_catch_up.py` holds 40 tests (the report says 38; its timing comes from
the health summary and was not re-measured), and 60 test modules import from `tests.test_toolkit`
(the report says 57).

## Evidence

### F01 · D3 narrows a review refusal that does not exist

Today only verify refuses a head behind the tip; review refuses nothing for being behind. D3 therefore
adds a new refusal at review (a conflicting merge only, exit 4 as at verify), extending `tip_gate` to
the review phase; its CURRENT text is §15.2 as it stands.

- ccp/prompt.py:473-480 — `def tip_gate(...)`: "a verify of a head behind the integration tip ... is
  refused"; `if phase != "verify": return []`
- docs/spec/02-delivery.md:1036-1041 (§15.6 rule 2) — "`ccp prompt verify` refuses a head that lacks
  code merged since (`behind_tip`...) before a verifier starts"
- docs/spec/02-delivery.md:857-928 (§15.2) — no behind-tip refusal for review
- docs/adr/0042 D3 — "`ccp prompt review` refuses a head behind the tip, beyond
  `merge.behind_tip_ignore`, only when merging the tip into it would conflict"

### F02 · Merge-tree and patch-id probes exist twice already

- ccp/lifecycle.py:1630 — `git(cfg.root, "merge-tree", "--write-tree", "-z", "--no-messages", head, tip)`
  with `STAGE_RE` parsing (1620)
- ccp/verify.py:733 — `git(cfg.root, "merge-tree", "--write-tree", "--no-messages", reviewed, base...)`
  without `-z`
- ccp/runs.py:371-386 — `_same_patch`: `g("fetch", "-q", "origin")`, then `patch-id --stable` against
  the merge base with `origin/<integ>`
- `git grep -n "merge-tree\|patch-id" -- ccp` → only lifecycle.py, verify.py and runs.py

Fix: one git merge helper module (a merge probe returning the tree and the conflicted files, an
own-patch-id helper with no fetch inside, a remerge-diff helper) that close, skip-review and the
integration-merge rule call, and D3, D4 and D5 build on (E14).

### F06 · Close's catch-up condition is restated outside the SPEC

- plugin/agents/delivery-runner.md:226-229 — "caught up by `ccp tasks close` itself when the merge is
